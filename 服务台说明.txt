服务台 ServiceHub 2.3 —— 本机自建服务统一管理器（Python 版）
================================================================================

【用途】
把近几个月在各个目录里攒下的自建服务、应用和运维脚本集中登记到一个常驻工作台：
以后不用再去 D:\WorkBuddy 各个工作区里翻目录、双击脚本，在工作台上点"启动/停止"
即可，状态一目了然；有网页入口的服务，启动后会自动把浏览器打开。
2026-10-31 由 PowerShell/WinForms 版整体替换为 Python + psutil + 浏览器界面；
同日升级到 2.1：加设置面板、浏览器选择、明暗主题、卡片/列表双视图、版本号与更新时间。
2.2：代码托管到 GitHub（笔记本可直接 clone）；新增本机差异层 services.local.json、
路径失效时显示「未安装」、依赖自举 setup-deps.bat、解释器锁定 runtime\python.txt。
2.3（2026-11-01）：源码审计修复——端口/注册表脏数据容错、Windows 端口占用探测、

【怎么启动（随便挑一种）】
  1. 桌面快捷方式「服务台」      —— 推荐，双击即可，自动打开控制台网页
  2. D:\Tools\服务台\启动服务台.bat —— 同上，没有快捷方式时用
  3. 浏览器直接开 http://127.0.0.1:9500/ —— 服务台已经在后台跑着时用它
  4. svc list / svc start docscan / svc stop docscan —— 命令行版（给脚本、计划任务用，
     详见 svc说明.txt，这条链路没动过）
  诊断：跑 启动服务台.bat --selftest，报告落在 logs\selftest-report.txt

【开机自启（2.3.1 新增）】
  设置面板 → 行为 → 开机自动启动，把开关拨开即可，不需要管理员权限。

  它到底写了什么（想手工核对就照这个看）：
    HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
      名称：ServiceHub
      类型：REG_SZ
      内容："…\pythonw.exe" "D:\Tools\服务台\ServiceHub.py" --no-open

  为什么这么设计：
    · 用 HKCU 而不是注册系统服务 / 计划任务 —— 免提权、杀软不拦、随用户登录拉起，
      和"托盘常驻"的定位一致；关掉只需删一个值，不留任何残留。
    · 用 pythonw.exe 而不是 python.exe —— 开机不会闪一下黑框。
    · 带 --no-open —— 开机只让托盘出现，不要抢着把浏览器弹出来打断你。
    · 不写进 runtime\settings.json —— 注册表才是唯一真相。你可能从
      「任务管理器 → 启动应用」直接关掉它，那样 settings.json 就会撒谎。

  怎么确认真的生效：
    1. 任务管理器 → 启动应用 → 找到 ServiceHub，状态应为"已启用"；
    2. 或者重启后看托盘里有没有服务台图标；
    3. 命令行核对：
       reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v ServiceHub

  怎么彻底取消：
    设置面板里关掉即可；也可以直接在任务管理器里禁用，或删掉上面那个注册表值。
    服务台下次打开设置时会如实显示当前状态（它是每次现读注册表的）。

  程序目录挪了怎么办：
    自启登记的是绝对路径。把 D:\Tools\服务台 整个搬走后，旧登记会指向不存在的路径。
    设置页会提示"登记的是旧路径"，把开关关一次再开一次就重写好了。

【换一台电脑（笔记本）怎么装】
  本目录已是一个 git 仓库，完整代码在 GitHub（私有）：
     https://github.com/gui8912/ServiceHub
  笔记本上只要：
     git clone https://github.com/gui8912/ServiceHub.git "D:\Tools\服务台"
     双击 启动服务台.bat
  第一次 clone 要登录：用户名填 GitHub 账号，密码处填 Personal Access Token
  （Settings → Developer settings → Personal access tokens → 勾 repo），
  登录一次后由 Windows 凭据管理器记住。
  首次运行会自动检查依赖：runtime\site-packages 里没有 psutil 就调用 setup-deps.bat，
  用本机 Python 3.10+ 把 psutil / pystray / Pillow 装进 runtime\site-packages
  （不动系统 Python）。想单独装、看详细报错就双击 setup-deps.bat。
  · 解释器会被记到 runtime\python.txt，下次启动固定用同一个：psutil/Pillow 带
    版本相关的二进制扩展，换小版本会 import 失败
  · runtime\、logs\、apps\ 都不入库（各自机器生成），克隆下来是干净的
  · services.json 里是台式机的绝对路径；笔记本上路径对不上的条目会显示灰色
    「未安装」，不会假装「已停止」。只改本机差异时，把 services.local.example.json
    复制成 services.local.json（已 gitignore，不会和仓库冲突）：
      默认按 id 合并覆盖字段；"remove": [id...] 隐藏条目；"mode": "replace" 整份替换

【文件清单】
  ServiceHub.py          前台入口：装好各模块、选端口、起后台采集线程和托盘
  启动服务台.bat          纯 ASCII 启动器（无 BOM / CRLF），负责拉起 pythonw
  hub\
    registry.py          services.json 读写与字段规范化（args 必须是数组）
    monitor.py           状态采集：psutil 每 1 秒一轮快照，接口只读结果
    actions.py           启动 / 停止 / 运行工具 / 打开网页 / 批量处理
    browsers.py          发现已装浏览器（Edge/Chrome/ego/Firefox/360）并按选择打开
    settings.py          设置模型：默认值、类型校验、原子落盘
    autostart.py         开机自启：只读写 HKCU\...\Run 的 ServiceHub 值，免提权
    meta.py              版本号与更新时间：注册表写了用写的，没写就从磁盘推断
    server.py            HTTP 服务与 REST 接口（只听 127.0.0.1）
    tray.py              系统托盘（pystray，缺了就自动降级为无托盘）
    ui\                  网页界面（index.html / style.css / app.js，零框架零 CDN）
  runtime\
    site-packages\       psutil / pystray / Pillow（随工具自带，不动系统 Python）
    settings.json        主题/视图/浏览器/刷新间隔/自动开网页等设置
    port.txt / hub.pid   本次运行的实际端口与进程号（给启动器读）
    _retarget_shortcut.py  桌面快捷方式重指向工具（不用 COM，见下文注意事项）
  services.json          服务注册表 —— 新增/修改服务只动这个文件，不用改代码
  services.local.example.json  本机差异层样例（复制成 services.local.json 生效，不入库）
  setup-deps.bat         依赖安装（纯 ASCII / 无 BOM / CRLF），换电脑时跑一次
  README.md              GitHub 首页说明（仓库地址、字段表、换机流程）
  .gitignore / .gitattributes  仓库忽略规则与换行符规则（bat 必须 CRLF）
  docs\                  界面截图（README 用）
  svc.cmd / svc.ps1      命令行版入口（PowerShell 实现，仍未变动）
  apps\                  各服务的目录联接（Junction，指向原目录，零拷贝）
  logs\                  运行日志（服务台自身 + 每个服务自己的输出）
  ServiceHub.ps1.legacy  旧 PowerShell/WinForms 版，留作回退，日常不再使用

【界面怎么用】
  · 两种视图，顶栏「卡片 / 列表」随时切换，选择会记住
      卡片：一张卡一个服务，信息横向铺开，适合一眼扫状态
      列表：一行一个服务，列为 服务 / 分组 / 版本号 / 更新时间 / 状态 / 端口 / 操作
            点任意表头按该列排序，再点一次反向（▲/▼）；分组、状态各占一列，同一行看完
  · 每张卡片/每行底部按钮
      启动 / 停止 / 重启 —— 常驻类服务；运行 —— 一次性脚本（体检、清理、注册表还原等）
      打开网页    —— 只在该服务真有地址时出现（服务没运行、或本来没有网页就不显示；
                    2.6.1 起不再摆一个点了没反应的灰按钮）。鼠标停上去会写明
                    「用 XX 浏览器打开」，点完的提示也带浏览器名
      日志        —— 该服务最近一次的输出（一次最多 300 行）。2.5.0 起只在**列表视图**
                    保留这个入口（卡片四列太挤）；要看日志就切到「列表」再点「日志」
      上次退出    —— 进程异常退出时显示退出码（主动停止不显示）
  · 卡片最底一行：操作按钮 + 右端版本号（2.5.1 起并成一行，卡片整体矮 34px）
      「更新于 YYYY-MM-DD」不再单独占一行：鼠标停在版本号上，提示里就是更新时间；
      要一眼看全更新时间，切到列表视图的「更新时间」列。
      版本号来自 services.json 的 version 字段；没写的尝试从 package.json /
      version.txt 推断，都没有就显示 —，不瞎编
      更新时间默认取该目录里最新一次文件改动时间（改了代码不用回来改日期）
  · 顶栏：视图切换 / 明暗主题 / 设置 / 刷新 / 全部启动 / 全部停止 / 退出
      "全部启动"会跳过 services.json 里标了 autostart:false 的桌面 GUI 工具
      （佳能扫描助手、NAPS2、视频号录制器、WeKnora 导入助手）——免得弹一堆窗口
      "全部停止"只停本工作台拉起的进程；外部运行的服务会列名提示但不动。
      真要结束外部实例，点那张卡的「停止」，再按提示二次确认（2.6.0 起）。
  · 工具栏：搜索框（名/说明/端口/版本/更新时间都搜）、分组筛选、右侧统计
      （共几项 / 运行中 / 工具数 / 本轮扫描耗时）
  · 状态颜色：绿=运行中，蓝=外部运行（不是工作台启动的），橙=启动中（进程已起、
      端口未通），紫=一次性工具，灰=已停止
  · 关掉浏览器标签页不会退出服务台，它仍在后台托管着各服务；
      真正退出用网页右上角"退出"，或托盘图标右键"退出服务台"

【首页布局怎么自己排（2.4 新增）】
  卡片视图固定**等宽四列**（窗口变窄自动退 3 / 2 / 1 列），17 条服务比原来少滚一屏。
  想改排布，点顶栏「布局」进入编辑模式（按钮变「完成」，<html> 加 edit-mode 类），
  改完再点一次「完成」退出。平时不进编辑模式，点卡片不会误拖。

  · 拖动卡片换位置 / 换分组（2.4.1 新增）
      编辑模式下按住卡片就能拖。拖到同组另一张卡的左半边=插到它前面，
      右半边=插到它后面；拖到别的分组区域=搬过去。
      落点有竖线提示（左/右各一条），拖到组内空白处会画整组虚线框=放到该组末尾。
      松手才写盘，中途拖到窗口外等于取消，什么都不改。
      组内先后存在 settings.json 的 service_order，跨组归属存在 service_group。
  · 拖动分组换序
      编辑模式下按住分组标题（整个标题栏都能按）上下拖，松手才写盘；
      拖动中该组半透明、下方留出落位虚线，位置无效会回滚。
      顺序存在 runtime\settings.json 的 group_order，未列出的分组按出现顺序接在后面。
      注意：搜索或分组筛选时只显示部分分组，这时拖顺序**不会保存**（免得把没显示的
      分组挤掉），会提示你切回「全部」清空搜索再拖。
  · 新建 / 改名 / 删除分组（2.5.0 新增）
      新建：编辑模式下内容区最底部「＋ 新建分组」，起个名字就出现一个空组，
            把卡片拖进去即可（空组里有"拖到这里"占位提示）。
      改名：编辑模式下分组标题右侧「改名」。组里的卡片跟着新名字走，
            记录也全部跟着改，不碰 services.json。
      删除：编辑模式下「删除」。纯自定义分组（卡片都是拖进来的）可以删，
            组内卡片会回到各自原来分组；如果这个组是某些服务在 services.json 里的
            原始分组，会拒绝并提示——先改名或把服务拖走。
  · 隐藏卡片
      编辑模式下每张卡右上角出现「眼睛（划线）」按钮，点一下从首页移除。
      被隐藏的服务**后台照样采集状态**（只是不画卡片），不是停用。
      编辑模式下列表底部会出现「已隐藏 N 个」，点名字即可恢复。
  · 折叠分组
      点分组标题左侧箭头。折叠状态记在浏览器本地（localStorage），
      不同浏览器各记各的；换机器不会带过去。
  · 组内批量启停
      分组标题右侧「启动本组 / 停止本组」。启动只挑没在跑、且不是 autostart:false 的；
      一次性脚本不参与（要用就单独点「运行」）。
  · 为什么隐藏/顺序不写进 services.json
      注册表只描述「服务是什么」，可见性、顺序、归属都是「我怎么看它」。
      存进 settings.json 后：手工改注册表、从 GitHub 重新 clone、别人给的
      services.json 覆盖过来，都不会冲掉你的布局；删掉的服务的残留 id 渲染时直接忽略。
      另外，网页里直接改写 services.json 风险太高——一旦格式写坏，得手改 JSON 才能救回来。
      所以卡片拖到别的组后，只在 service_group 里记一笔 {服务id: 分组名} 覆盖显示；
      把它拖回注册表原本的组时，这条覆盖会自动删掉，不留垃圾。
  · 后悔药
      设置 → 首页布局 → 「恢复默认顺序」：一次清空分组顺序、卡片顺序、跨组归属，
      全部还原成 services.json 里的样子（隐藏的卡片不受影响，另有恢复入口）。

【设置面板（顶栏齿轮）】
  外观
    主题        跟随系统 / 明亮 / 暗色。跟随系统会随 Windows 明暗模式自动切换
    默认视图    卡片 / 列表
    界面密度    舒适 / 紧凑。舒适=说明两行、间距宽松；紧凑=说明一行、间距收紧。
                两档都是等宽四列，版本号都在操作按钮行右端，不另占一行
    自动刷新    每 1 / 2 / 5 / 10 秒，或暂停
    背景动效    开 / 关，默认【关】。关掉后页面彻底静止；打开则三团光斑缓慢漂移。
                部分浏览器 + 集显组合下持续运动会整屏闪烁，所以才做成可选（见下方闪烁章节）
  首页布局

【REST 接口（给脚本用，全部只听 127.0.0.1）】
  GET  /api/status          全部服务状态（含 version/updated/state/portText/url/lastExit）
  GET  /api/settings        设置 + 已装浏览器 + 关于信息 + 开机自启状态（autostart）
  GET  /api/logs?id=xxx     某个服务最近输出（id=__hub__ 看服务台自身日志）
  POST /api/action          {id, action: start|stop|restart|run|open, force?}
  POST /api/batch           {action: start-all|stop-all}
  POST /api/settings        改设置（只改传入字段，非法值会被纠正而不是照单全收）
                            可写字段：auto_open / browser / browser_path / theme /
                                      view / refresh_ms / bg_motion
                            另有 autostart（true/false），它写注册表、不进 settings.json，
                            返回体里的 message 会说明成功与否
  POST /api/browser/test    用指定浏览器打开服务台
  POST /api/reload          强制重读 services.json
  POST /api/exit            退出服务台（不影响已启动的业务服务）
  ★ 所有 POST 必须带请求头 X-ServiceHub: 1，否则返回 403。
    这是防跨站用的：别的网站没法偷偷启停你本机的服务。
  ★ 请求体上限 1MB；Content-Length 不合法或超限分别返回 400 / 413。

【页面一直在闪怎么办】
  正常状态下，页面上唯一会动的只有背景那 3 个缓慢漂移的光斑；卡片本身不会重建，
  也不会自动刷新。如果闪得像在按 F5，按下面顺序排查：

  第一步：先按 F5 刷新一次。CSS/JS 虽然是 no-store 不缓存，但已经开着的旧标签页
          仍在使用内存里的旧样式，不刷新看不到改动。

  第二步：用诊断参数把原因夹死（左下角会出现橙色角标，去掉参数即恢复）：

          http://127.0.0.1:9500/?fx=noanim    只停背景光斑动画
          http://127.0.0.1:9500/?fx=noblur    只关毛玻璃（backdrop-filter）
          http://127.0.0.1:9500/?fx=off       两样都停，页面应当彻底静止

          哪个不闪了，原因就是哪个。若 ?fx=off 仍然闪，说明与页面样式无关。

  第三步：若 ?fx=off 还闪，问题在浏览器/显卡，与本站无关：
          ① 打开任意其他网页对比——别的页面也闪，就是浏览器硬件加速的问题，
             到浏览器设置里关掉「使用硬件加速」再看；
          ② 更新或重装显卡驱动；
          ③ 换一个浏览器打开同一地址对比。

  实测记录（2026-11-01，本机 Intel 集显 + 高 DPI）：
          Edge 闪、ego 不闪，同一台机器同一个地址。用 Chrome 抓帧量化，
          页面帧间像素差仅 0.2/765（基本静止），因此判断为 Edge 的合成路径问题。
          进一步用 ?fx=noanim 确认：**闪的就是背景光斑的漂移动画**，与毛玻璃无关。
          2.3.1 因此把光斑漂移改成默认关闭。改完复测：连抓 5 帧字节完全相同
          （页面彻底静止，17 张卡片、0 个运行动画）。
          若仍闪，请按第三步查浏览器硬件加速。

  想恢复"呼吸感"又不想闪：设置 → 外观 → 背景动效 → 开，观察一段时间；
  一旦又开始闪，说明这个显卡/浏览器的组合扛不住持续合成，关回去即可。

【重要提醒】
  1. 服务台网页只监听 127.0.0.1，局域网其他机器访问不到（这是有意的安全限制）
  2. 起始端口 9500，被占用时自动往上找（9500-9519）；实际端口看 runtime\port.txt
  3. 重复双击不会开出第二个工作台：检测到已有实例就直接复用它并打开网页
  4. 退出服务台不等于关掉已启动的服务，它们继续跑；要全关就先点"全部停止"
  5. 本机建 .lnk 的 COM 接口被安全策略拦过，桌面快捷方式是用
     runtime\_retarget_shortcut.py 直接改字节的（保留原 IDList，改完按结构体回读
     校验通过）；要恢复原样就把 runtime\DesktopShortcut-ServiceHub.lnk.bak
     复制回桌面、改名「服务台.lnk」
  6. 新增服务：编辑 services.json 追加一条即可，args 必须是数组（写成字符串会被逐字符
     拆开）；改完不用重启工作台，最多 1 秒后就能在页面上看到
  7. 首次运行不要用 open(path,'wb') 之类的方式改这些文件做"校验"，
     历史上就是这么把 ServiceHub.ps1 截成 0 字节的
